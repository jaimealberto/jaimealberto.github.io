“Nadie está hablando de esto.” Así empieza el post de LinkedIn que lleva semanas circulando. La combinación: Claude Code con NotebookLM como memoria externa. El resultado prometido: un agente IA con memoria infinita, montado en dos minutos.

Me lo monté. Lo probé. Esto es lo que encontré.

Qué es esta combinación y por qué genera ruido

Claude Code es el CLI de Anthropic — una IA que opera directamente en la terminal, lee ficheros, ejecuta comandos y trabaja con tu entorno real. Si lo usas, ya sabes de qué va.

NotebookLM es la herramienta de Google para organizar documentos. Le subes PDFs, vídeos, notas de audio, y puedes hacerle preguntas sobre ese contenido. Actúa como un sistema RAG (Retrieval-Augmented Generation): la IA no inventa — consulta tus documentos y cita las fuentes.

El problema: NotebookLM no tiene API pública. La “combinación secreta” consiste en un script de GitHub que usa Playwright — un automatizador de navegador — para que Claude Code controle NotebookLM desde la terminal como si fuera un humano haciendo clic. Login automático, crear notebooks, hacer consultas, recibir respuestas.

La idea tiene su lógica: usas NotebookLM como base de conocimiento y Claude como capa de razonamiento e interacción. Para quien no tiene nada más, es un atajo interesante.

Lo probé: así fue

El problema estructural que nadie menciona

Antes de entrar en si funciona bien o mal, hay un problema de fondo que conviene nombrar.

Playwright sobre una interfaz web es frágil por diseño. Estás automatizando clics y formularios HTML que Google puede cambiar en cualquier momento sin previo aviso. Una actualización de NotebookLM y el script deja de funcionar. No es un bug — es la naturaleza de la solución. No hay API estable detrás.

Tus documentos van a Google. NotebookLM procesa el contenido en servidores de Google Cloud. Para documentos públicos o genéricos, esto es irrelevante. Para documentos técnicos internos, notas de auditoría, o cualquier cosa sensible, es un punto a considerar antes de subir nada.

¿Vale la pena si ya tienes un homelab?

Aquí el artículo se bifurca. La respuesta cambia radicalmente dependiendo de tu punto de partida.

Si partes de cero

Si no tienes un sistema de notas estructurado, ni un vault, ni ninguna integración de IA con tus documentos, esta combinación tiene sentido. Montas NotebookLM con tus PDFs, conectas Claude Code, y en poco tiempo tienes algo que funciona. Es el camino más corto hacia un asistente IA con contexto real.

La fricción de Playwright es un coste asumible si la alternativa es construir todo desde cero.

Si ya tienes homelab o Obsidian

El panorama cambia. Si ya usas un vault de Obsidian, un NAS, o cualquier estructura de documentación propia, probablemente ya tienes — sin saberlo — el equivalente de lo que ofrece esta combinación. Y sin depender de Google.

Comparativa directa:

Lo que promete la combinación Alternativa self-hosted
NotebookLM como base de conocimiento Vault Obsidian + búsqueda local
RAG sobre tus documentos Meilisearch o cualquier motor de búsqueda local
Memoria persistente para Claude CLAUDE.md + ficheros de memoria locales
Consultas sobre PDFs y notas Claude lee directamente tus ficheros

La diferencia clave: en el stack self-hosted, nada sale de tu máquina. Claude lee los ficheros directamente, sin intermediarios, sin APIs de terceros, sin riesgo de que un cambio en la interfaz de Google rompa el flujo.

El propio hilo de comentarios del post lo confirma. Varios usuarios señalan que la solución basada en Obsidian hace lo mismo — y de forma más estable.

Cuándo sí elegiría esta combinación

No todo es blanco o negro. Hay casos en los que NotebookLM + Claude Code tiene ventajas reales:

  • Audio y vídeo: NotebookLM procesa grabaciones y vídeos de YouTube de forma nativa. Si tu base de conocimiento incluye mucho contenido multimedia, eso es difícil de replicar localmente sin montar transcripción automática.
  • Sin infraestructura propia: para quien no tiene servidor, NAS ni Obsidian, es el camino más rápido.
  • Colaboración: NotebookLM permite compartir notebooks. Si necesitas que varias personas accedan al mismo contexto, tiene sentido.

Para uso individual en un entorno con homelab, estas ventajas raramente pesan más que los inconvenientes.

Conclusión

Lo que me llevo de este experimento: la combinación Claude Code + NotebookLM resuelve un problema real — darle a la IA acceso a tu conocimiento acumulado. Pero lo resuelve con herramientas externas cuando la solución más robusta y privada ya estaba disponible en local.

Si tienes diez minutos y curiosidad, pruébalo. Si tienes una tarde y un NAS, monta el stack local.
