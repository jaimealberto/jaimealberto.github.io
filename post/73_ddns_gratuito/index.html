Si sigues los artículos anteriores (VPS en Oracle Cloud, relay WireGuard) ya tienes un servidor en la nube con una IP pública. El problema es que esa IP puede cambiar — Oracle asigna IPs “ephemeral” que raramente rotan, pero no hay garantía. Y si tienes un servidor en casa, tu ISP cambia la IP cada vez que se reinicia el router.

La solución es un servicio de DNS dinámico (DDNS): un nombre de dominio que siempre apunta a tu IP actual, actualizado automáticamente cuando cambia.

Este artículo cubre dos opciones completamente gratuitas, con distinto nivel de sofisticación.

Nota: Este artículo describe configuraciones para proyectos personales, homelab y aprendizaje. Los servicios gratuitos mencionados tienen sus propios Términos de Servicio — respétalos. No uses estos dominios para actividades ilegales, spam ni suplantación de identidad.

Opción 1 — DuckDNS: el más sencillo

DuckDNS es el punto de entrada ideal. Sin instalaciones, sin configuración de nameservers, sin cuenta de pago. En cinco minutos tienes un subdominio tudominio.duckdns.org apuntando a tu servidor.

Registro y creación del subdominio

  1. Ve a duckdns.org e inicia sesión con GitHub, Google, Twitter o Reddit — no crea cuenta nueva, usa tu cuenta existente.
  2. En el campo “sub domain”, escribe el nombre que quieras. Por ejemplo: miservidor → obtienes miservidor.duckdns.org.
  3. Haz clic en “add domain”. Aparece en tu lista con la IP actual.
  4. Anota el token que aparece en la parte superior de la página — lo necesitarás para el script.

Cliente en Linux — actualización automática

DuckDNS no instala nada en el sistema. El cliente es un script de una línea que se ejecuta periódicamente con cron.

# Crea el directorio y el script
mkdir -p ~/duckdns
cat > ~/duckdns/duck.sh <<'EOF'
echo url="https://www.duckdns.org/update?domains=TUDOMINIO&token=TU_TOKEN&ip=" | curl -k -o ~/duckdns/duck.log -K -
EOF
chmod +x ~/duckdns/duck.sh

Sustituye TUDOMINIO por tu subdominio (sin .duckdns.org) y TU_TOKEN por el token de tu cuenta.

Prueba que funciona:

~/duckdns/duck.sh
cat ~/duckdns/duck.log
# debe mostrar: OK

Automatiza con cron para que se ejecute cada 5 minutos:

crontab -e

Añade esta línea:

*/5 * * * * ~/duckdns/duck.sh >/dev/null 2>&1

A partir de ese momento, cada vez que tu IP cambie, DuckDNS lo detectará en los siguientes 5 minutos y actualizará el registro.

Verificar que funciona

dig +short tudominio.duckdns.org
# debe devolver tu IP pública actual

curl ifconfig.me
# compara con el resultado anterior — deben coincidir

Cuándo usar DuckDNS

DuckDNS es perfecto para:

  • Acceso remoto a un servidor doméstico o de laboratorio
  • Relay VPN propio (como el que describimos en el artículo anterior)
  • Cualquier servicio que necesite un nombre fijo pero no requiera un dominio “presentable”

La limitación es el aspecto: tudominio.duckdns.org es funcional pero identifica inmediatamente el servicio como algo casero. Si quieres algo más neutro o con tu nombre propio, la opción 2 es mejor.

Opción 2 — qzz.io con Cloudflare: un dominio propio sin coste

DigitalPlat FreeDomain es un proyecto sin ánimo de lucro respaldado por The Hack Foundation (organización 501(c)(3) de EEUU). Ofrece subdominios gratuitos en varios dominios propios — el más usado es .qzz.io, aunque también hay .us.kg, .dpdns.org y .xx.kg.

La diferencia con DuckDNS: aquí tú gestionas el DNS con tu propio proveedor (Cloudflare, en este caso). Tienes control total sobre los registros — A, CNAME, MX, TXT, lo que necesites.

Paso 1 — Cuenta gratuita en Cloudflare

Antes de registrar el dominio necesitas tener Cloudflare configurado para poder darle los nameservers.

  1. Crea una cuenta en cloudflare.com — el plan gratuito es suficiente para todo lo que vamos a hacer.
  2. Una vez dentro, ve a Add a Site (o “Añadir un sitio”).
  3. Escribe el dominio que vas a registrar en DigitalPlat — por ejemplo tunombre.qzz.io.
  4. Selecciona el plan Free.
  5. Cloudflare te mostrará dos nameservers con nombres del tipo: 
    xxx.ns.cloudflare.com
yyy.ns.cloudflare.com
    Anótalos — los necesitarás en el paso siguiente.

No te preocupes si Cloudflare dice que no puede verificar el dominio todavía — es normal, porque aún no hemos asignado los nameservers en DigitalPlat.

Paso 2 — Registrar el dominio en DigitalPlat

  1. Ve a domain.digitalplat.org e inicia sesión con tu cuenta de GitHub — es el único método de autenticación (sirve como verificación de identidad).
  2. Haz clic en Register Domain.
  3. Elige el sufijo que quieres (.qzz.io, .us.kg, etc.) y escribe el subdominio: por ejemplo tunombre → obtienes tunombre.qzz.io.
  4. En la configuración del dominio, selecciona Custom Nameservers y pon los dos nameservers que te dio Cloudflare en el paso anterior.
  5. Confirma el registro.

La propagación de nameservers puede tardar entre unos minutos y 24 horas, aunque normalmente es cuestión de minutos.

Paso 3 — Configurar los registros DNS en Cloudflare

Una vez que Cloudflare verifica que controla el dominio (te llega un email de confirmación), puedes añadir registros DNS desde el panel:

DNS → Records → Add record

Para apuntar el dominio a tu servidor:

Tipo Nombre Contenido Proxy
A tunombre.qzz.io IP de tu servidor ☁️ sí (opcional) o DNS only

Si activas el proxy de Cloudflare (la nube naranja), el tráfico HTTP/HTTPS pasa por los servidores de Cloudflare — añade protección contra DDoS y oculta tu IP real. Para SSH o WireGuard, desactívalo (DNS only, nube gris) — Cloudflare no proxifica UDP ni SSH.

Paso 4 — DDNS automático desde el servidor

A diferencia de DuckDNS, qzz.io no tiene un cliente propio. Para actualizar automáticamente la IP cuando cambia, usas la API de Cloudflare.

Primero necesitas dos datos del panel de Cloudflare:

  • Zone ID: en la página principal del dominio, columna derecha
  • API Token: My Profile → API Tokens → Create Token → usar la plantilla “Edit zone DNS”

Script de actualización DDNS via API de Cloudflare:

#!/bin/bash
# ddns-cloudflare.sh — actualiza el registro A de un dominio en Cloudflare

ZONE_ID="TU_ZONE_ID"
RECORD_ID="TU_RECORD_ID"   # ver más abajo cómo obtenerlo
API_TOKEN="TU_API_TOKEN"
DOMAIN="tunombre.qzz.io"

IP_ACTUAL=$(curl -s https://ifconfig.me)

curl -s -X PATCH \
  "https://api.cloudflare.com/client/v4/zones/${ZONE_ID}/dns_records/${RECORD_ID}" \
  -H "Authorization: Bearer ${API_TOKEN}" \
  -H "Content-Type: application/json" \
  --data "{\"type\":\"A\",\"name\":\"${DOMAIN}\",\"content\":\"${IP_ACTUAL}\",\"ttl\":60}"

Para obtener el RECORD_ID de tu registro A:

curl -s -X GET \
  "https://api.cloudflare.com/client/v4/zones/TU_ZONE_ID/dns_records?type=A&name=tunombre.qzz.io" \
  -H "Authorization: Bearer TU_API_TOKEN" | python3 -m json.tool | grep '"id"'

Automatiza con cron cada 5 minutos:

chmod +x ~/ddns-cloudflare.sh
crontab -e
# añade:
*/5 * * * * ~/ddns-cloudflare.sh >/dev/null 2>&1

Mi configuración

En mi caso uso ambas. DuckDNS en el servidor de Oracle Cloud para el cliente DDNS nativo — es el más sencillo de mantener cuando el servidor es un relay y no quiero añadir dependencias. Para el dominio de investigación uso qzz.io gestionado en Cloudflare, que me permite tener varios subdominios bajo el mismo dominio y gestionar todo desde un panel centralizado.
