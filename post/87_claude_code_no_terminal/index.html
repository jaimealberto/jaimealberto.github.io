Claude Code para los que odian la terminal

31-12-2026
Sysadmin, IA

Sun Tzu escribió que el maestro guerrero no moviliza su ejército dos veces para la misma batalla. El que repite es el que no preparó el terreno.

La mayoría usa IA como un buscador mejorado. Escribe una pregunta, lee la respuesta, la aplica a mano. Tres pasos por tarea. Al día siguiente, los mismos tres pasos.

Eso no es construir un sistema. Es copiar a mano.

Claude Code es la diferencia. Y lo mejor: no necesitas amar la terminal para aprovecharlo.

Prompt vs sistema: la diferencia real

Hay dos formas de usar IA. La primera: abres el chat, escribes una pregunta, lees la respuesta, la aplicas a mano. La segunda: construyes un sistema que lo hace por ti.

Un prompt es una pregunta que haces una vez. Un sistema es un flujo que se ejecuta solo.

La diferencia no es técnica. Es de mentalidad.

Con un prompt generas un resultado. Con un sistema generas resultados, cada vez, sin esfuerzo adicional. Claude Code es exactamente la herramienta para pasar de uno a otro — sin necesitar ser programador ni dominar la terminal.

Sin terminal: Desktop app y VS Code

Claude Code tiene fama de herramienta de terminal. Técnicamente lo es — pero hay dos formas de usarlo sin que veas una sola línea de bash:

Desktop app (Mac y Windows)

Anthropic lanzó la app nativa de Claude Code para escritorio. Se instala como cualquier aplicación: descarga, doble clic, listo. Abre proyectos, ejecuta tareas, mantiene historial de sesiones. El resultado es idéntico al de la terminal — sin la pantalla negra que intimida.

Extensión de VS Code

Si ya usas Visual Studio Code, Claude Code se integra directamente en el editor. No cambias de ventana, no abres una terminal: el chat vive en el sidebar y los cambios aparecen en el editor en tiempo real.

Para sysadmins que trabajan con ficheros de configuración, playbooks de Ansible o manifiestos YAML, esto transforma el flujo: editas nginx.conf, describes lo que quieres cambiar y Claude Code lo hace delante de tus ojos — con diff incluido para revisar antes de aceptar.

CLAUDE.md: enseñarle el contexto una sola vez

La queja más repetida con los asistentes IA: “Tengo que explicarle lo mismo cada vez.”

Claude Code lo resuelve con CLAUDE.md — un fichero de texto plano en la raíz de tu proyecto. Lo escribes una vez: quién eres, cómo trabajas, qué herramientas usas, qué nunca debe tocar. No vuelves a repetirlo.

Ejemplo mínimo para un homelab:

# Mi infraestructura

- Servidor principal: proxmox01 (Proxmox VE, 192.168.1.10)
- Backups en: nas01 (NAS, /data/backups)
- Nunca usar sudo — escalar con su -
- Siempre hacer backup antes de editar un fichero remoto
- Responder en español de España, tuteando

Claude Code lee ese fichero al inicio de cada sesión. Sabe dónde está tu infraestructura, cómo acceder a ella y qué reglas respetar. No necesitas decirle nada más.

Para alguien que gestiona un homelab o una infraestructura corporativa, esto solo ya justifica el cambio respecto al chat web.

Skills: comandos / que no tienes que explicar

Las Skills son flujos de trabajo reutilizables que defines una vez y ejecutas con /nombre-del-skill.

Casos de uso reales:

/revisar-pr          → revisa el pull request activo según tus reglas
/publicar-articulo   → ejecuta el flujo completo de publicación del blog
/audit-seguridad     → comprueba puertos abiertos y reglas del firewall
/cierre-sesion       → actualiza notas, hace commit y cierra limpio

Cada Skill es un fichero Markdown en .claude/skills/. Lo escribes tú — o le pides a Claude Code que lo genere basándose en lo que haces habitualmente. Una vez definido, /audit-seguridad ejecuta exactamente eso, con tus servidores, tus herramientas, tu infraestructura.

No necesitas programar nada. Si sabes describir en texto lo que quieres hacer, sabes crear una Skill.

MCP: conectar tus herramientas sin código

MCP (Model Context Protocol) es el protocolo que permite a Claude Code hablar directamente con tus herramientas: servidores SSH, bases de datos, APIs, gestores de contraseñas, vault de notas.

Desde fuera parece técnico. Por dentro, la configuración es un bloque JSON de 10 líneas en ~/.claude.json. Y la comunidad ya ha construido cientos de servidores MCP listos para usar — sin escribir una línea de código.

Algunos ejemplos que uso en el homelab:

  • harper-ssh → ejecuta comandos en servidores directamente desde el chat
  • harper-obsidian → lee y escribe notas en el vault de Obsidian
  • harper-keepass → accede a credenciales de forma segura sin exponer contraseñas en el chat

La serie completa de MCPs del homelab arranca en el artículo 56. Lo importante aquí: configurar un MCP no requiere saber programar. Requiere copiar un bloque de configuración y reiniciar Claude Code.

Modo autónomo: delega y no vuelvas

El modo autónomo de Claude Code cambia la dinámica completamente.

En modo normal, Claude Code pide confirmación antes de cada acción: ¿puedo editar este fichero? ¿puedo ejecutar este comando? Útil para aprender, pesado para tareas rutinarias que ya conoces y confías.

En modo autónomo, le das la tarea y te vas. Claude Code ejecuta, verifica, corrige y notifica cuando termina — como un técnico al que delegas trabajo y te llama cuando está listo.

Combinado con /loop — que mantiene a Claude Code trabajando en ciclos hasta completar el objetivo — puedes delegar tareas largas: actualizar toda la documentación del homelab, revisar cincuenta artículos del blog para SEO, auditar configuraciones de seguridad en diez servidores.

El sistema trabaja. Tú haces otra cosa.

Por dónde empezar

Si nunca has usado Claude Code, el orden que recomiendo:

  1. Instala la app de escritorio — sin terminal, sin fricción, en cinco minutos
  2. Crea un CLAUDE.md en la carpeta de tu proyecto — descríbele tu entorno en cinco líneas
  3. Prueba una tarea concreta — “revisa este fichero de configuración y dime qué mejorarías”
  4. Define tu primera Skill — el flujo que más repites
  5. Añade un MCP — empieza por harper-obsidian o cualquier servidor MCP de la comunidad

No es un salto. Es una escalera. Cada peldaño da resultado antes de subir al siguiente.

Sun Tzu también escribió que el guerrero victorioso gana primero y lucha después.

El “enemigo” aquí no es la IA ni la terminal. Es el tiempo que gastas repitiendo tareas que podrías haber delegado.

La terminal no es el obstáculo. La falta de sistema, sí.
